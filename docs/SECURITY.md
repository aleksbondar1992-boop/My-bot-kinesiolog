# Утечка ключей в истории репозитория

**Статус: требует действия. Репозиторий публичный.**

## Что произошло

Файл `bot1.py` (SMM-бот на Groq) был загружен с ключами, вписанными в код как
значения по умолчанию:

```python
TELEGRAM_TOKEN = os.getenv("TELEGRAM_TOKEN", "<токен вписан прямо здесь>")
GROQ_API_KEY   = os.getenv("GROQ_API_KEY",   "<ключ вписан прямо здесь>")
```

Файл потом удалили — но удаление файла **не удаляет его из истории git**.
Оба секрета лежат открытым текстом в 8 коммитах и достаются одной командой
`git log -p`. Репозиторий публичный, то есть ключи доступны кому угодно и,
с высокой вероятностью, уже собраны сканерами.

Текущий `main` чистый: в `bot.py` только `os.environ`, значений по умолчанию нет.
Это не отменяет утечку — история открыта.

## Чем это грозит

| Ключ | Что может чужой |
|---|---|
| Токен Telegram-бота | Полностью забрать бота: читать всё, что ему пишут, и писать от его имени |
| Ключ Groq | Слать запросы за ваш счёт |

## Что делать — по порядку

1. **Отозвать токен Telegram.** @BotFather → `/revoke` → выбрать бота.
   Старый токен умирает мгновенно, бот и его подписчики остаются.
   Новый токен — сразу в переменные окружения хостинга, не в код.
2. **Отозвать ключ Groq.** Консоль Groq → удалить ключ → создать новый.
3. **Проверить расход** по обоим сервисам за период с даты первой заливки —
   не было ли чужой активности.
4. **Только после этого** — решение о чистке истории (см. ниже).

Порядок важен: чистка истории без отзыва ключей бесполезна. Копии репозитория,
форки и кеши поисковиков останутся, а ключи в них — живыми.

## Чистка истории

Опционально и необратимо: переписывает все коммиты и требует force-push.
Делать только после отзыва ключей и только осознанно.

- `git filter-repo --path bot1.py --invert-paths` (или BFG Repo-Cleaner)
- затем force-push всех веток
- у всех, кто клонировал репозиторий, локальные копии станут несовместимы

Альтернатива для публичного репозитория: сделать его приватным или создать
чистый репозиторий заново и перенести туда только текущий код.

## Чтобы не повторилось

- Никаких значений по умолчанию у `os.getenv` для секретов — пусть падает с
  ошибкой, если переменная не задана
- `.gitignore` для `.env`
- Загрузка файлов через веб-интерфейс GitHub опаснее коммита из редактора:
  легко залить черновик с ключами, не глядя
