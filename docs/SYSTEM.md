# Система управления ботами

Рабочий документ по боту практики кинезиолога Александра Бондаря.
Визуальная версия: артефакт «Пульт кинезиолога».

## 1. Что работает сегодня

Снято с `bot.py` в этом репозитории.

| | |
|---|---|
| Канал | Telegram, long polling |
| Библиотека | `python-telegram-bot 20.3` |
| Мозг | Gemini 2.0 Flash по REST |
| Роль | помощник кинезиолога, УТП «боль за 1 приём или бесплатно» |
| Запись | текстом отправляет к `@alexbond9232` |
| Команды | `/start` |
| Секреты | `TELEGRAM_BOT_TOKEN`, `GEMINI_API_KEY` в переменных окружения — в коде ключей нет |
| Сборка | nixpacks, конфиг пустой (сборка по умолчанию) |

## 2. Чего не хватает

| Приоритет | Пробел | Последствие |
|---|---|---|
| критично | Нет памяти диалога | Каждое сообщение уходит в модель отдельно, без истории. Уточняющий вопрос бот не понимает. |
| критично | Ничего не сохраняется | Ни контактов, ни вопросов. Написавший человек теряется. |
| важно | Нет лимита на расход ИИ | Цикл сообщений от одного пользователя = неограниченный счёт за API. |
| важно | Нет ВКонтакте | Аудитория сообщества ВК до бота не доходит. |
| важно | Любая правка = деплой | Приветствие или цену нельзя поменять без коммита и передеплоя. |
| потом | Нет запасного сценария | Ошибка Gemini → «Ошибка. Напишите: @alexbond9232». Ни повтора, ни второй модели. |

## 3. Архитектура

```
Пациент в TG ──Bot API──┐
                        ├─► Шлюз каналов ─► Ядро ─┬─► ИИ-слой (Gemini)   [промпт ↔ ответ]
Пациент в ВК ─Callback──┘   TG/VK-адаптер   сессия └─► Хранилище          [диалоги, заявки]
                            антиспам        память         │
                                              ▲            │ метрики
                                              │ настройки  ▼
                                          Панель управления
```

Ключевое решение: панель не встроена в бота. Она пишет настройки и читает данные,
поэтому тексты, цены и лимиты меняются без передеплоя.

## 4. Разделы панели

| Раздел | Что делает |
|---|---|
| Входящие | Все переписки TG и ВК в одном списке. «Отвечаю сам» отключает бота в диалоге. |
| Заявки | Имя, канал, контакт, жалоба, статус: новая / в работе / записан / отказ. |
| Боты и каналы | Подключение, токены, проверка связи, пауза, «стоп всем». |
| База знаний | Промпт, цены, адрес, УТП, ответы на частые вопросы — правится без деплоя. |
| Сценарии | Приветствие, кнопки, что спросить до записи, дожим при молчании. |
| Рассылки | Сегменты (был на приёме / не дошёл / спрашивал про спину), TG и ВК раздельно. |
| Аналитика | Диалоги, заявки, конверсия, пиковые часы — по каналам. |
| Расходы | Токены и рубли по дням, лимит на пользователя и на сутки. |

## 5. Каналы

**Telegram** — бот регистрируется в @BotFather, токен бесплатно; приём через polling
(как сейчас) или webhook; рассылки только тем, кто сам написал боту.

**ВКонтакте** — не отдельный бот, а *сообщество*: ключ доступа выдаётся в его
настройках, приём через Callback API или Long Poll, нужны права администратора.
Рассылки удобнее через Senler — подписки живут внутри ВК.

## 6. Порядок внедрения

Шаги зависимые, порядок менять нельзя.

1. **Память и база** — история диалога и контакты. Закрывает два критичных пробела.
2. **Заявки и лимиты** — бот собирает контакт и создаёт заявку; потолок расхода на ИИ.
3. **Панель** — обзор, входящие, заявки, база знаний, расходы. Делается после базы:
   раньше ей нечего показывать.
4. **ВКонтакте** — VK-адаптер к уже проверенному ядру; логика и промпт общие.
